Hardware checks against rated rates.

One script per platform and GPU vendor. Each reads the machine, compares the parts with the rates that build should hold, and names the most likely software-side limiter. No install, no changes.

  • Windows 10 / 11
  • Read-only
  • Report to Desktop

Per GPUNVIDIA reads clocks, power limit and temperature through nvidia-smi. AMD and Intel get link and display checks only.

02. Coverage

What every script compares

CPU clock

Rated base clock, sustained clock under an all-core load, power-plan CPU cap, memory integrity.

Memory

Configured speed against the platform target, channel count, capacity, module identity.

PCIe link

Width and generation the card actually trained at, plus the card default power limit on NVIDIA.

Display

Current refresh rate against the maximum the adapter reports.

Storage

Sequential write and uncached read on the system drive, against the speed of its class.

Power and heat

Peak draw estimate, idle ACPI thermal zones and post-load temperature.

03. Reading it

One summary line, then the detail

  • PASSAt or above the baseline for this platform.
  • WARNWorking, but below what the setup should hold.
  • FAILOutside the baseline, or the wrong part for the script.
  • SKIPNot exposed by Windows, or needs administrator rights or a vendor tool.

The console ends with a likely limiter and up to three findings, and the same text is written to a report on the Desktop. A build that passes every row is running at the rates its parts were sold at; a failing row names the subsystem to look at before buying anything.

  • PSU wattage is not readable. Only the label has it. The script prints the peak draw it expects.
  • Thermal zones need administrator rights. Without them, CPU temperatures are skipped, not guessed.
  • AMD and Intel GPU sensors are not exposed. Use Adrenalin or Arc Control for clocks and power limits.
  • Only the system drive is benchmarked. Other drives are listed but not tested.
